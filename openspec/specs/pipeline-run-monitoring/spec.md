# pipeline-run-monitoring Specification

## Purpose
定義管線在排程、無人看管執行時，如何留下每次執行的摘要與異常告警，讓使用者不必盯著執行過程，也能事後判斷那次有沒有跑成功、有沒有需要處理的問題。
## Requirements
### Requirement: 每次執行寫出摘要

每次執行管線（不論成功或失敗）結束時，系統 SHALL 寫出 `data/run_summary.json`（覆蓋上次），內容至少包含：開始時間、結束時間、耗時、結果（成功/失敗）、爬到的筆數、萃取成功與失敗筆數、新寫入待審的筆數、判定為已知案而跳過的筆數、其中疑似舊案的筆數；失敗時另外包含失敗的階段與錯誤訊息。

#### Scenario: 成功執行後摘要反映本次結果

- **WHEN** 管線完整跑完，本次新增 2 筆待審
- **THEN** `run_summary.json` 的結果為成功、新增待審筆數為 2，結束時間為本次執行時間

#### Scenario: 中途失敗仍寫出摘要

- **WHEN** 管線在萃取階段拋出例外
- **THEN** `run_summary.json` 的結果為失敗，並記錄失敗階段與錯誤訊息；尚未執行的階段欄位為空

### Requirement: 異常時追加告警

系統 SHALL 在以下任一情況，追加一筆告警到 `data/alerts.log`（只追加、不覆蓋）：① 管線執行拋出例外而中止；② 萃取失敗筆數佔萃取總筆數的比例 ≥ 10%。每筆告警 SHALL 包含時間、告警類型與可判讀的說明。正常執行時 MUST NOT 寫入告警。

#### Scenario: 管線失敗產生告警

- **WHEN** 資料庫連線失敗導致管線中止
- **THEN** `alerts.log` 多一筆「管線失敗」告警，且管線以非 0 的結束代碼結束

#### Scenario: 萃取失敗比例過高產生告警

- **WHEN** 本次萃取 100 筆、失敗 12 筆
- **THEN** `alerts.log` 多一筆「萃取失敗比例過高」告警，說明中含 12/100

#### Scenario: 失敗比例低於門檻不告警

- **WHEN** 本次萃取 172 筆、失敗 1 筆
- **THEN** `alerts.log` 沒有新增任何內容

### Requirement: 排程執行入口

系統 SHALL 提供一個可直接交給 Windows 工作排程器呼叫的執行入口，執行完整管線、把輸出附加到執行 log，並以管線的成功與否回傳結束代碼；文件 SHALL 說明如何在 Windows 工作排程器設定這個入口。

#### Scenario: 排程器依結束代碼判斷成敗

- **WHEN** 工作排程器執行該入口，而管線失敗
- **THEN** 入口回傳非 0 的結束代碼，執行 log 中有本次的完整輸出
